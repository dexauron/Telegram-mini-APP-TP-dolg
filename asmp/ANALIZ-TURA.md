## 3. Панорамы

Исходники — равнопромежуточные **10000×5000** (комментарии в XML), на выдачу
нарезаны в **кубические карты**: шесть граней на сцену, три набора качества.

Вес первой сцены, набор для десктопа:

| Грань | Байт |
|---|---|
| 0 (перед) | 744 420 |
| 1 (право) | 946 087 |
| 2 (зад) | 454 734 |
| 3 (лево) | 949 688 |
| 4 (верх) | 942 946 |
| 5 (низ) | 938 357 |
| **Итого** | **4 976 232 ≈ 4,7 МБ** |

Три сцены в десктопном качестве — около **14 МБ**. Наборы `tablet` и `mobile`
побайтово одинаковы (230 268 байт на грань), то есть разделение на два профиля
существует в разметке, но не в файлах: планшет качает ту же картинку, что и телефон.

## 4. Сцены и точки

Три панорамы:

| Сцена | Идентификатор | Название в туре |
|---|---|---|
| 1 | `pano11661` | `2726 copy` |
| 2 | `pano11662` | `2727 copy` |
| 3 | `pano11663` | `2729 copy` |

Названия сцен — имена файлов из папки фотографа
(`/Users/romanizmajlov/3D/skkkooooor/pano/size/size222/2726 copy.jpg`), в интерфейс
они попали как есть.

Точек **23**: 17 в стиле `IconDefaultPointSpotStyle2` и 6 в `IconDefaultPointSpotStyle` —
те самые кружки с «i» на скриншоте. Все подсказки к ним **пустые**:

```xml
<data name="ru_spotmap11630_tooltip"><![CDATA[]]></data>
<data name="ru_spotmap11631_tooltip"><![CDATA[]]></data>
... и так все пятнадцать
```

То есть точки работают только как переходы между панорамами. Что за оборудование
в кадре, тур не объясняет — это самый крупный пробел и самое простое место,
где наш вариант оказывается полезнее.

## 5. Интерфейс

Панель внизу (видна на скриншоте) собрана в скине из кнопок:

`ibtn_up` `ibtn_down` `ibtn_left` `ibtn_right` — поворот обзора
`ibtn_sounds_on` / `off` — звук
`ibtn_autorotate_on` / `off` — автовращение
`ibtn_openfs` / `ibtn_closefs` — полноэкранный режим
`ibtn_hidecontrols` — спрятать панель

Плюс план помещения из `floorplan/map2_copy.jpg` и режим WebVR с отдельным
экраном настроек шлема (межзрачковое расстояние, дисторсия, хроматическая аберрация).

## 6. Что тянется на страницу

| Файл | Вес |
|---|---|
| jQuery 2.1.1 | 84 245 байт |
| jQuery UI 1.11.1 | 238 314 байт |
| jQuery UI touch-punch | — |
| KolorTools | 17 426 байт |
| KolorBootstrap | 13 342 байт |
| Загрузчик krpano | 162 014 байт |
| Flash-объект `.swf` | 116 693 байт |

Около **630 КБ** обвязки до того, как начнёт грузиться первая панорама. jQuery UI
здесь нужен ради нескольких ползунков в настройках VR. Flash-ветка мертва: Adobe
прекратил поддержку в конце 2020 года, ни один современный браузер её не исполнит.

Ещё деталь: в `<security>` стоит `<allowdomain domain="*" />` — тур разрешает
встраивать себя с любого домена.

## 7. Выводы для нашего проекта

**Что перенимаем.** Саму идею: полноэкранный тур без страничной обвязки, панель
управления внизу по центру, круглые точки, план помещения, переключение сцен.
Пользователь сразу оказывается внутри машины — это правильное решение.

**Что делаем иначе.**

| Слабое место оригинала | Наше решение |
|---|---|
| Плеер требует лицензии | Свой движок на WebGL, three.js как единственная зависимость |
| 630 КБ обвязки на jQuery | Обвязки нет, код страницы целиком |
| Flash-фолбэк не работает | Без WebGL — текстовая карта узлов с азимутами |
| Точки без подписей | Карточка узла: назначение, параметры, роль в телемедицине |
| Названия сцен — имена файлов | Осмысленные названия и подписи |
| `tablet` и `mobile` одинаковы | Один набор, размер под предел видеопамяти устройства |
| Кубические карты, 18 файлов на сцену | Равнопромежуточная панорама, один файл на сцену |
| 14 МБ на три сцены | Вес задаётся качеством ваших снимков, грузится только открытая сцена |

**Чего не копируем.** Панорамы, план помещения и фотоматериалы: это съёмка
правообладателя, на ней выставочные машины ГАЗ, а не автомобили центральной
станции Грозного. Под видом своих они и юридически чужие, и по сути не те.
Разметка, стили и движок написаны заново — а панорамы снимаются ваши.
