# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Проект: «Мост долгов» (рабочее название)
**Telegram Mini Web App для учёта долговых обязательств между поставщиками и магазинами**

---

## 1. Общие положения

### 1.1. Цель проекта
Создать бесплатное мини-приложение в экосистеме Telegram, которое позволяет поставщикам продуктов и сотрудникам продуктовых магазинов:
- фиксировать долговые записи (заявки на оплату, заказы, отсрочки платежа);
- отслеживать сроки выплат через календарь;
- обмениваться медиа-материалами (фото накладных, видео товара, документы);
- формировать отчёты для руководства;
- оценивать надёжность контрагентов через рейтинговую систему.

### 1.2. Целевая аудитория
- Поставщики продуктов питания (оптовики, производители, дистрибьюторы).
- Собственники и сотрудники продуктовых магазинов (закупщики, бухгалтера, администраторы).
- Руководство обеих сторон, которому нужны сводные отчёты.

### 1.3. География
Российская Федерация и республики (с учётом законодательства РФ, включая 152-ФЗ «О персональных данных»).

### 1.4. Платформа
- **Основной канал:** Telegram (бот + Mini Web App).
- **Дополнительный канал приглашений:** WhatsApp, SMS, email, прямые ссылки, QR-коды.

### 1.5. Монетизация
Проект полностью бесплатный для всех пользователей на всех этапах.

### 1.6. Принципы
- **Простота:** минимум кликов, интуитивный интерфейс, никакого обучения не требуется.
- **Скорость:** все операции выполняются за 1–3 касания.
- **Безопасность:** изоляция данных между конкурентами, двустороннее подтверждение операций.
- **Шариат:** отсутствие процентов (рибы) за просрочку, обязательная цифровая фиксация долга.
- **Надёжность:** данные не теряются, система доступна 24/7.

### 2.4. Статусы записей (FR-026 — FR-038)

**Жизненный цикл записи:**
```
Черновик → На согласовании → Активна → [Частично оплачена] → Оплачена
                                    ↓
                              Просрочена
                                    ↓
                                Отменена
```

| ID | Требование | Приоритет |
|---|---|---|
| FR-026 | **Черновик** — запись создана, но ещё не отправлена контрагенту (только через Web App). | Обязательно |
| FR-027 | **На согласовании** — запись отправлена контрагенту, ожидает его подтверждения или отклонения. | Обязательно |
| FR-028 | **Активна** — обе стороны подтвердили запись. Долг зафиксирован. | Обязательно |
| FR-029 | **Частично оплачена** — внесена часть суммы, остаток указан в записи. Переход в «Оплачена» после погашения остатка. | Обязательно |
| FR-030 | **Оплачена** — полная сумма погашена. Перевод в этот статус требует подтверждения **обеих сторон** (антимошенничество). | Обязательно |
| FR-031 | **Просрочена** — автоматический статус, если дата оплаты прошла, а запись не в статусе «Оплачена». | Обязательно |
| FR-032 | **Отменена** — запись отменена по соглашению сторон или отклонена контрагентом на этапе согласования. | Обязательно |
| FR-033 | Перевод в статус «Оплачена» возможен только после подтверждения обеих сторон. Если одна сторона отмечает оплату, а вторая не подтверждает — запись остаётся в предыдущем статусе с пометкой «Ожидает подтверждения оплаты». | Обязательно |

## 6. Потоки данных (основные сценарии)

### Сценарий 1: Создание записи через Web App
1. Пользователь открывает Mini Web App.
2. Выбирает активный профиль (если несколько).
3. Нажимает «+ Новая запись».
4. Заполняет форму: сумма, дата оплаты, описание, контрагент (из списка или по username).
5. Прикрепляет медиа (опционально).
6. Нажимает «Отправить на согласование».
7. Система создаёт запись в статусе «На согласовании».
8. Контрагент получает уведомление с кнопками «Подтвердить» / «Отклонить».
9. При подтверждении — статус «Активна». При отклонении — «Отменена».

### Сценарий 2: Создание записи в личном чате
1. Пользователь А пишет в чат пользователю Б: «@BotName 5000 руб за молоко, оплата 15 августа».
2. Бот парсит сообщение и отвечает карточкой-предпросмотром.
3. Пользователь А нажимает «✓ Создать».
4. Запись отправляется пользователю Б на согласование.
5. Если Б не зарегистрирован — бот отправляет приглашение.
6. Далее — как в Сценарии 1 (п. 8–9).

### Сценарий 3: Подтверждение оплаты
1. Сторона А открывает запись и нажимает «Отметить оплату».
2. Система отправляет уведомление стороне Б: «Сторона А отметила оплату записи №1042 на сумму 45 000 ₽. Подтвердите?»
3. Сторона Б нажимает «Подтвердить оплату».
4. Запись переходит в статус «Оплачена».
5. Обе стороны получают уведомление об успешном закрытии записи.
6. Открывается возможность оставить отзыв (в течение 7 дней).

### Сценарий 4: Формирование отчёта
1. Пользователь открывает раздел «Отчёты».
2. Выбирает период (неделя / месяц / произвольный).
3. Выбирает формат: PDF или текст.
4. Система генерирует отчёт.
5. Пользователь нажимает «Поделиться» → выбирает чат (личный или групповой) или копирует текст / скачивает PDF.

### Сценарий 5: Просрочка платежа
1. Система ежедневно проверяет записи со статусом «Активна».
2. Если дата оплаты прошла — статус автоматически меняется на «Просрочена».
3. Отправляются уведомления обеим сторонам (согласно настройкам пользователей).
4. Запись выделяется в списке и календаре.

### 7.1. Нижняя навигация (3 вкладки)

## 8. Ограничения и допущения

### 8.1. Ограничения
- Проект работает только в экосистеме Telegram (основной функционал).
- Медиа-файлы хранятся в Telegram — при удалении чата файлы становятся недоступны.
- Проект бесплатный — без платных подписок и рекламы.
- Валюта фиксирована — только рубли.
- Нет интеграции с банковскими системами (только учёт, не переводы).

### 8.2. Допущения
- Пользователи имеют активный Telegram-аккаунт.
- Пользователи добросовестны (система не защищает от злонамеренного отказа подтверждать оплату — это решается через доверие и рейтинг).
- Telegram API остаётся доступным и бесплатным.
- Проект не требует лицензирования как финансовый сервис (только учёт обязательств).
