# Приход по накладной → Штрих-М: Торговое предприятие 7

Страница для оператора 1С. Она берёт строки бумажной накладной, находит каждый товар
в справочнике магазина, переводит упаковки в штуки и сохраняет файл, который
загружается в приходную накладную штатной кнопкой 1С. Оператор проверяет только
спорные строки. Подтверждённые пары страница запоминает, и в следующий раз строки
этого поставщика подставляются сами.

Сервер не нужен. Файл `index.html` открывается двойным щелчком, данные остаются
в браузере.

## Как работать

1. **Справочник — один раз.** В 1С откройте справочник «Штрих коды», затем
   «Ещё → Вывести список» и «Сохранить как» `.xlsx`. На странице нажмите
   «1. Справочник» и выберите этот файл. Когда справочник обновится, загрузите
   его снова.
2. **Накладная.** Укажите поставщика, итог по накладной и вставьте строки.
   Страница принимает три формата:
   - таблицу из Excel: наименование, кол-во, ед., цена, сумма, код поставщика;
   - Markdown-таблицу в колонках бланка 1С — так отвечает ИИ по промту оператора;
   - JSON распознавания (формат — в `fixtures/*.json`).
3. **Проверка.** Цвет строки показывает, насколько надёжно сопоставление:

   | Цвет | Что значит | Что делать |
   |---|---|---|
   | без цвета | запомнено, найдено по штрихкоду, совпало дословно или ИИ предложил наименование, которое есть в справочнике | ничего |
   | жёлтый | почти наверняка этот товар | посмотреть и нажать «Подтвердить все жёлтые» |
   | оранжевый | есть похожие, выбор за оператором | выбрать из списка или найти поиском |
   | красный | в справочнике нет | «+ Новый товар» — завести в 1С отдельно |

   Если сумма строк не сходится с «Итого» или «кол-во × цена ≠ сумма», скорее
   всего, при распознавании ошибка в цифре. Строка подсвечивается.
4. **Выгрузка.** «Скачать файл для 1С». Затем в 1С: Приходная накладная →
   «Заполнить» → «Загрузить из файла…» → «Из внешнего файла» →
   «Загрузить таблицу из файла».

## Что делает с цифрами

- **Упаковки → штуки.** Вложение берётся из накладной: «упак (12 бут)», колонка
   «Коэф», пара цен «за Уп.» / «за Шт.». Если вложения нет, страница просит его
   указать и запоминает для этой строки поставщика.
- **Цена = сумма / количество**, округление до копейки. Сумма выгружается из
   накладной без изменений.
- **Весовой товар остаётся в кг.** Если в накладной кг, а в 1С товар штучный
   (или наоборот), строка подсвечивается.
- **Колонка «Штрих-код»** заполняется штрихкодом штучной единицы из справочника.
   1С ищет по нему в первую очередь, поэтому товар находится однозначно.
   Код поставщика попадает в «Код товара у поставщика».

## Как устроено

| Файл | Что внутри |
|---|---|
| `index.html` | интерфейс |
| `core.js` | разбор справочника и вставки, сопоставление, упаковки, проверки, выгрузка |
| `core.test.js` | тесты: `node --test tools/prihod/core.test.js` |
| `fixtures/` | строки настоящих накладных для тестов |
| `vendor/xlsx-0.20.3.full.min.js` | [SheetJS](https://sheetjs.com), Apache-2.0: чтение и запись Excel без интернета |

Товар в справочнике ищется так, чтобы находились сокращения поставщиков
(«ВиногКлюкЕжевКлуб» → «Виноград Клюква Ежевика Клубника»), и чтобы кириллица
сравнивалась с латиницей («Вискас» ↔ «Whiskas»). Сравнение учитывает вес или
объём (другой вес — другой товар), жирность и бренд. Балл сходства стоит рядом
с каждым кандидатом.

## Чего пока нет

**Распознавания фото.** Сейчас строки приходят готовыми: из Excel, от ИИ или
из JSON. Anthropic API в России недоступен, поэтому распознавание подключается
отдельно. Основной кандидат — Yandex Vision OCR с моделью для таблиц. Ядро от
способа распознавания не зависит.
