# Мост долгов

Telegram Mini App для учёта долговых обязательств между поставщиками и магазинами.
Фиксация договорённостей с подтверждением обеих сторон, календарь платежей, напоминания.

Бесплатно для пользователей — всегда. Стек рассчитан на рост до 500 000 зарегистрированных
и стартует на бесплатных тарифах Supabase и Cloudflare Pages.

## Архитектура

```
Telegram (бот + inline) ─┐
                         ├─► Supabase Edge Functions ─► Postgres (RLS + RPC + pg_cron)
Mini App (Cloudflare) ───┘                                     │
        ▲                                                      │
        └──────────────── Supabase Realtime ◄──────────────────┘
```

- **Postgres** — единственный источник правды. Машина состояний сделки реализована
  `SECURITY DEFINER` RPC-функциями, поэтому её нельзя обойти из браузера.
- **RLS** — клиенту доступно только чтение и только своих сделок. Профили, с которыми
  не было сделок, невидимы: конкуренты не находят друг друга.
- **Edge Functions** — вебхук бота, обмен Telegram `initData` на JWT, отправка уведомлений.
- **pg_cron** — ежедневные задачи в 00:01 МСК: заморозка зависших споров, напоминания
  о просрочке и о приближающемся сроке, авто-подтверждение платежей.

### Структура репозитория

```
docs/                        анализ ТЗ и принятые решения
supabase/migrations/         схема БД, RLS, RPC, планировщик
supabase/tests/              сквозной тест машины состояний
supabase/functions/          Edge Functions
  _shared/                   разбор сообщений, форматирование, подпись Telegram, JWT
  auth/                      обмен initData на JWT
  telegram-webhook/          бот: инлайн-режим, deep link, кнопки
  outbox-worker/             рассылка уведомлений с учётом лимитов Telegram
  report/                    отчёты текстом и таблицей, доставка ботом
web/                         Mini App: React + TypeScript + Vite
```

### Тесты

```bash
supabase/tests/run.sh                    # база: миграции + машина состояний
supabase/functions/_shared/run-tests.sh  # разбор сообщений, форматирование, подпись, JWT
cd web && npm run build && npm run smoke  # интерфейс в настоящем браузере
```

Первый скрипт поднимает временный Postgres, имитирует окружение Supabase, накатывает
все миграции и прогоняет сквозной сценарий: создание сделки, акцепт, частичная оплата,
переговоры, сплит остатка, заморозка спора, аннулирование по согласию, ежедневные
сводки. Заодно проверяется изоляция данных — посторонний не видит ни сделок, ни
статистики и не может перехватить чужую карточку.

Второй проверяет разбор фраз вроде «5000 руб за молоко, оплата 15 августа», русские
склонения и форматы сумм, а также отклонение поддельного и просроченного `initData`.
Зависимостей и сети не требуется — только Node 22.

Третий открывает собранное приложение в Chromium с подставленными данными и проверяет,
что экраны рисуются, суммы и просрочка считаются, а исключений JavaScript нет.

## Схема данных

| Таблица | Назначение |
|---|---|
| `app.users` | Аккаунт Telegram. Телефон, ФИО и прочие ПДн не хранятся |
| `app.profiles` | Профиль поставщика или магазина. Сделки привязаны к профилю, а не к аккаунту |
| `app.deals` | Сделка: сумма в копейках, срок, статус, предложение об изменении условий |
| `app.payments` | Платежи по сделке с подтверждением второй стороны |
| `app.attachments` | Вложения — только `file_id` Telegram, файлы у себя не храним |
| `app.invites` | Приглашения контрагентов по deep-link |
| `app.audit_log` | Журнал всех действий |
| `app.outbox` | Очередь уведомлений: не теряются и не дублируются |

Полезные представления: `app.deals_view` (остаток, признак просрочки, частичная оплата)
и `app.bilateral_stats` (приватная двусторонняя статистика вместо публичного рейтинга).

Сделку, созданную без указания контрагента (инлайн-карточка), принимает тот, кто нажал
«Подтвердить» — Telegram не сообщает боту адресата инлайн-сообщения. Чтобы такую карточку
нельзя было перехватить, `app.rpc_create_deal` выпускает одноразовый токен приглашения,
и без него `app.rpc_accept_deal` сделку не примет.

## Развёртывание

### 1. Supabase (бесплатный тариф)

1. Создайте проект на [supabase.com](https://supabase.com), регион — ближайший к РФ (Frankfurt).
2. **Settings → API → Exposed schemas**: добавьте `app` к списку (по умолчанию там только `public`).
   Без этого шага клиент не увидит таблицы.
3. **Database → Extensions**: включите `pg_cron` и `pg_net`.
4. Примените миграции по порядку — через SQL Editor или Supabase CLI:

```bash
supabase link --project-ref <ваш-ref>
supabase db push
```

5. Пропишите настройки для планировщика (значения возьмите в Settings → API):

```sql
insert into app.settings (key, value) values
  ('outbox_worker_url', 'https://<ref>.supabase.co/functions/v1/outbox-worker'),
  ('service_role_key',  '<service_role_key>')
on conflict (key) do update set value = excluded.value;
```

### 2. Бот

1. Создайте бота у [@BotFather](https://t.me/BotFather), сохраните токен.
2. `/setinline` — включите инлайн-режим (без этого не работает создание записи из чата).
3. `/setinlinefeedback` — включите обратную связь, иначе бот не узнает о выборе карточки
   и не сможет дописать в неё кнопку подтверждения.
4. `/setmenubutton` — укажите URL Mini App.

### 3. Edge Functions

Секреты (Project Settings → Edge Functions → Secrets):

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_BOT_USERNAME` | имя бота без `@` — из него собираются ссылки-приглашения |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка, ею подписывается вебхук |
| `MINI_APP_URL` | адрес Mini App на Cloudflare Pages |
| `SUPABASE_JWT_SECRET` | из Settings → API, им подписываются токены пользователей |

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам.

```bash
# Ни Telegram, ни Mini App не присылают Supabase-JWT — свои проверки внутри функций.
supabase functions deploy auth --no-verify-jwt
supabase functions deploy telegram-webhook --no-verify-jwt
supabase functions deploy outbox-worker --no-verify-jwt
supabase functions deploy report --no-verify-jwt
```

Подключите вебхук (секрет должен совпадать с `TELEGRAM_WEBHOOK_SECRET`):

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<ref>.supabase.co/functions/v1/telegram-webhook",
    "secret_token": "<TELEGRAM_WEBHOOK_SECRET>",
    "allowed_updates": ["message","inline_query","chosen_inline_result","callback_query","my_chat_member"]
  }'
```

### 4. Mini App

Cloudflare Pages: корневой каталог `web`, сборка `npm run build`, каталог сборки `dist`.

| Переменная | Что это |
|---|---|
| `VITE_SUPABASE_URL` | адрес проекта Supabase |
| `VITE_SUPABASE_ANON_KEY` | публичный ключ; доступ к данным ограничивает RLS, а не секретность ключа |
| `VITE_BOT_USERNAME` | имя бота без `@` — для ссылок-приглашений |

Локально: `cd web && npm install && npm run dev`. Вне Telegram приложение честно
сообщает, что открывать его нужно из мессенджера: без подписанного `initData` входить
некуда.

### Экраны

- **Записи** — список с фильтрами, суммы «мне должны» и «я должен», поиск, кнопка создания.
- **Карточка записи** — условия, платежи, блок «было / стало» при переговорах, история
  действий, действия по статусу: подтвердить, отметить оплату, предложить условия,
  перенести срок по остатку, предложить аннулирование.
- **Календарь** — месяц с цветными отметками, сводка по дню и за месяц.
- **Профиль** — переключение профилей, приватная статистика по контрагентам, отчёты
  за период, настройки напоминаний.

Отчёт формируется на сервере и приходит от бота в личный чат: текстом — чтобы переслать
руководителю, таблицей CSV — для бухгалтерии. Доступ к приложению получателю не нужен
(FR-085). Файл открывается в Excel без настройки импорта: разделитель «;», кодировка
UTF-8 с BOM, суммы с запятой.

## Стоимость

Для пользователей приложение бесплатно всегда. Расходы на инфраструктуру зависят от
числа активных пользователей:

| Активных пользователей | Инфраструктура | В месяц |
|---|---|---|
| до ~5 000 | Supabase Free + Cloudflare Pages | **0 ₽** |
| ~10 000 | Supabase Pro | ~$25 |
| ~100 000 | Supabase Pro + доп. ресурсы | ~$50–80 |
| ~500 000 | Supabase Pro + вебхук на Cloudflare Workers | ~$100–200 |
| ~500 000 | свой Postgres на выделенном сервере | ~€25–40 |

Архитектура рассчитана на 500 000 пользователей без переписывания: журнал
секционирован, плановые уведомления свёрнуты в ежедневные сводки, очередь рассылки
разнесена во времени. Подробный расчёт — в [`docs/02-masshtabirovanie.md`](docs/02-masshtabirovanie.md).
